# Stakeholder Matrix & User Personas

## 1. User Personas

### Persona 1: Aarav — Student

**Primary Objectives**
- Find academic references quickly
- Avoid late fines

**Key Frustrations**
- Long physical queues
- Unexpected fine accumulation

**Target Platform Features**
- Mobile search portal
- Push/email due-date alerts

---

### Persona 2: Mrs. Sunita — Librarian

**Primary Objectives**
- Process checkouts quickly
- Maintain accurate catalog inventory

**Key Frustrations**
- Manual record entries
- Stock discrepancies
- Lost books

**Target Platform Features**
- Barcode issue/return interface
- Automated fine tracker

---

### Persona 3: Dr. Verma — Library Administrator

**Primary Objectives**
- Monitor library utilization
- Generate departmental compliance reports

**Key Frustrations**
- Lack of real-time usage data
- Manual report generation taking days

**Target Platform Feature**
- Executive analytics dashboard with one-click PDF export

## 2. Stakeholder Responsibility Matrix

| Stakeholder Group | Stakeholders | Responsibilities / Expectations |
|---|---|---|
| Business Stakeholders | College Management, Library Admin, Students, Faculty | Define business vision, validate functional usability and ensure domain compliance |
| Engineering Stakeholders | Software Developers, UI/UX Designers, QA Engineers | Architect codebase, build responsive frontends and ensure high quality through testing |
| Operations Stakeholders | DevOps Engineers, Database Administrators, Security Team | Provision infrastructure, maintain database integrity, automate CI/CD pipelines and support security |
